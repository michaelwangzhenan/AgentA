先写 spec，定验收标准，设计测试，
再让 coding agent 实现，
然后靠测试、review、trace、diff 和回归来收货

Vibe 出原型，Eval 守质量

Agent 分工
Agent A 资料调研与竞品分析只看公开信息，输出结构化报告。
Agent B 产品 spec 起草基于调研结果，定义功能边界和验收标准。
Agent C 前端代码实现只看 spec 和 UI 设计稿，不碰后端。
Agent D 后端 API 实现只看 spec 和数据模型，不碰前端。
Agent E 测试用例生成与执行基于 spec 写测试，跑通后报告通过率。
Agent F 文档与 README，基于代码和 spec 生成用户文档。
Agent G 反向审查检查所有 agent 输出的一致性、冲突和遗漏。


failure mode 怎么踩到的
幻觉：模型自信地编造不存在的 API、论文、数据、人名。
上下文遗忘：长对话到后半段，前面的约束被默默丢掉。
过度服从：你说什么它都说好，不纠正你的错误前提。
工具调用翻车：该搜索不搜索，该调函数时参数传错。
长链路漂移：多步任务做到第四五步偏离主线，最终结果跑偏。
格式失控：JSON 多逗号、Markdown 嵌套错、代码缩进乱。
安全幻觉：生成看似正确的代码，但藏着安全漏洞。
