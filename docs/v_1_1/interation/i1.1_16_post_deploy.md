# 1. 底部 log 美化

## 1.1. 背景 
ICP备案和公安备案都已经通过，并且把连接和logo 加到了页面底部。
但是现在看起来很low, 需要进行优化，使其看起来高端大气

## 1.2. 需求

### 1.2.1. 目标

全站底部备案栏视觉降噪：信息合规完整，样式参考百度主页底部细条（单行、极薄、半透明深色底、浅色小字），存在感低但不影响审核可读性。

### 1.2.2. 展示范围

登录页与主界面（聊天区等）均展示同一贴底底栏，全站一致。

### 1.2.3. 内容

从左到右单行排列，项之间用空格或「·」分隔，不用竖线。

产品链接（页面未就绪，点击 toast「页面建设中」）：

- 关于 AgentA
- 使用须知
- 帮助中心
- 隐私政策
- 联系我们

合规信息：
- 浙ICP备2026055936号-1，链至 beian.miit.gov.cn
- 公安备案官方图标 + 浙公网安备33010502013300号，链至 beian.mps.gov.cn 查询页

### 1.2.4. 布局

贴底浮层：fixed bottom-0，横跨页面宽度，浮在内容上方。主内容区预留底部 padding（约 pb-8），避免最后一条消息或表单被遮挡。底栏 z-index 低于弹窗，高于普通内容。

### 1.2.5. 样式

- 背景：半透明深色 scrim + backdrop-blur；底栏与页面主题解耦，不跟 warm/amber 皮肤变色
- 浅色主题：bg-black/50 text-white/85
- 深色主题：dark:bg-black/70，并加 dark:border-t dark:border-white/10 划出顶边，避免条带与深底融在一起
- 文字：text-xs，hover 略提亮并下划线
- 高度：约 28–32px，单行优先，窄屏允许换行
- 公安图标约 14px，与文字垂直居中；图标 alt 写「公安备案图标」；深色 scrim 下实测可读，必要时微调亮度，不换官方图

### 1.2.6. 主题切换

底栏采用固定 scrim + 浅色字，不走 background / muted-foreground 等 token。切主题时交互不受影响，但深色皮肤下条带边界可能变淡，需靠更高透明度与顶边线兜底。


# 2. 如何对外展示

## 2.1. 背景
根据公安审核，注册需要实名。但个人实体没有资质，就去掉了注册功能

## 2.2. 扩展用户管理

1. 在设置 → 用户管理页面增加「新建用户」
2. 在用户管理页面可更改用户角色（user ↔ admin）
3. 用户管理仅主账号可操作：用户名等于 AUTH_ADMIN_USERNAME（默认 admin）的账号；其它账号即使角色为 admin，也不能新建 / 改角色 / 删用户

### 2.2.1. 需求分析

#### 2.2.1.1. 角色分层

系统里有两层权限，不要混为一谈：

- 角色 admin：可访问 Skills、MCP、系统配置、API 密钥、数据库、备份、离线评估等高级功能（与现有 require_admin 门禁一致）
- 主账号（用户名 = AUTH_ADMIN_USERNAME）：在 admin 角色之上，额外拥有用户管理（新建 / 改角色 / 删除）

对外开通时默认给 user 角色；用人单位技术人员如需评估技术深度，可申请升为 admin 角色，但仍不能操作用户管理。

#### 2.2.1.2. 新建用户

- 入口：设置 → 用户管理 →「新建用户」（仅主账号可见该入口）
- 字段：用户名、初始密码、角色（默认 user，可选 admin）
- 后端：POST /api/admin/users，依赖主账号校验（非仅 require_admin）
- 创建成功返回用户信息，不下发 cookie（与旧公开注册不同）
- 用户名规则与现有一致：1–64 字符、大小写不敏感去重

#### 2.2.1.3. 更改角色

- 主账号可在用户列表把 user 升为 admin，或把 admin 降回 user
- admin 账号只读（不可改角色、不可删除）

#### 2.2.1.4. 删除用户

- 沿用现有删除能力，同样仅主账号可操作
- admin 账号除外（见上）

#### 2.2.1.5. 后端与前端改动点

- 后端 deps 新增 require_super_admin（校验用户名 = AUTH_ADMIN_USERNAME），用户管理相关端点从 require_admin 改为此依赖
- 前端 access.ts：settings/users 从「admin 角色可进」改为「主账号可进」
- 前端 SettingsPage：用户管理导航项仅主账号显示；UserManagement 组件加新建用户表单与角色切换

## 2.3. 面向外部

1. 登录页增加提示：本站不开放注册，如需体验请通过底栏「联系我们」联系主账号
2. 新增「联系我们」页面（未登录可访问），展示电话、邮件、微信二维码、LinkedIn、GitHub 源码链接等
3. 普通用户（role=user）登录后，主界面顶部展示 banner：「如需体验完整功能，请申请管理员权限」（链至联系我们页）

注意：产品能力无法对未登录访客直接展示，登录页与联系我们页需单独做视觉打磨，作为对外第一印象。

### 2.3.1. 需求分析

#### 2.3.1.1. 访客路径

未登录访客只能看到登录页、联系我们页，以及底栏合规链接。底栏「联系我们」从 toast 改为跳转 /contact；其余产品链（关于、使用须知等）暂保留「页面建设中」。

App.tsx 需支持公开路由：/contact 不要求登录；其它路径逻辑不变。

#### 2.3.1.2. 联系我们页

- 路由 /contact，登录前后均可访问
- 联系方式放配置文件（如 frontend/public/site.json），避免硬编码进组件
- 内容项：电话、邮件、微信（文字说明 + 可选二维码图）、LinkedIn、GitHub 仓库链接
- 附一句说明：体验账号与 admin 角色均由主账号人工审核开通，不开放自助注册

#### 2.3.1.3. 登录页提示

登录表单下方一行小字：「本站不开放注册。如需体验账号或申请 admin 角色，请通过底栏联系我们。」

#### 2.3.1.4. 普通用户提示

role=user 登录后，主界面顶部固定展示 banner：「如需体验完整功能，请申请管理员权限」。「申请管理员权限」链至 /contact。

侧栏 admin 专属入口（Skills、MCP、设置里的系统配置等）对 user 仍不可见；若通过深链误入，ForbiddenView 保留简短无权限说明。

#### 2.3.1.5. 视觉（单独验收）

登录页与联系我们页作为对外门面，风格与主应用一致但信息层次更清晰（可参考左文案 + 右表单的登录布局）。底栏 §1 已统一，本节不重复。
