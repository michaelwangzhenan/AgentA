# 性能优化

## 入库解析

- 入库前检查 DOCX 解压大小，超限文件拒绝解析。
- 大文件放到独立子进程解析，限制内存和执行时间，避免拖死服务。
- 自动跳过 `~$` 开头的 Office 临时文件。
- 分块处理解析结果，减少完整文本及中间副本同时驻留内存。

设计方案：

- DOCX 在调用 python-docx 前统计 ZIP 解压总量，超过 64 MiB 直接报错。
- 解析放入独立子进程；Linux 设置 512 MiB 硬限制，父进程统一执行 120 秒超时和异常回收。
- 子进程把清洗后的段落写入临时流；父进程按章节增量分块，并分批写入 Chroma 和 BM25，保留现有标题路径、行号、内容哈希和总分块数字段。
- Web 上传、批量扫描和解析入口三层过滤 ~$ 临时文件。
- 三个限制作为配置项同步到 .env、.env.example、后端配置和设置界面。
- 测试覆盖解压超限、超时、内存超限、临时文件、标题元数据、幂等入库及批量写入。

本次实现：

- DOCX 解压上限为 64 MiB，解析子进程上限为 512 MiB，超时为 120 秒。
- DOCX 解析结果按标题区段分块，通过临时文件分批写入，保留原有元数据和内容哈希。
- Web 上传、批量扫描和解析入口均过滤 Office 临时文件。
- 其他文件格式及数据库结构保持不变。

## BM25

- 不在内存中长期保存整库正文、分词结果和词频副本。
- 文件入库时增量更新，避免每次重算并写入整个索引。
- 增加从 Chroma 重建 BM25 的工具，处理索引不一致。

设计方案：

- 索引只持久化 metadata、词频和文档长度；正文检索时按 chunk id 回 Chroma 取。
- 文档频率与平均长度增量维护，入库时只更新受影响 chunk，不再全库重算。
- 批量入库结束时统一写盘一次；单文件上传在文件完成后写盘一次。
- 新增 rag_cli bm25-rebuild，从 Chroma 分批重建索引。

本次实现：

- bm25_index 升级为 v2 紧凑格式；兼容读取旧版 pkl。
- ingest_all 改为整批结束后 commit；ingest_one 单文件结束后 commit。
- retriever 的 BM25 命中回表取正文；管理端 L3 详情同样回表。
- 命令：python tools/cli/rag_cli.py bm25-rebuild -m <alias>

## 服务保护

- 限制并发入库数和单次入库资源。
- 在解析、分块、嵌入、Chroma 写入和 BM25 更新的开始、完成及异常节点记录日志。
- 日志包含文件名、文件大小、解压大小、分块数、阶段耗时、进程内存和系统可用内存。
- 关键日志立即写入文件，避免死机时仍停留在缓冲区。
