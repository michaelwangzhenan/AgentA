## 2. P0

### 2.1 Agent.run 直接 NameError

位置：src/agent/agent.py（约 20 行 import、302 行使用）

提交 f07415d（SSE 与并发保护）把 `from src.agent.core.citation_builder import CitationBuilder` 换成了 run_cancel 的 import，但 run() 里仍在 `CitationBuilder()`。本地实测 `Agent().run('hi')` 报 `NameError: name 'CitationBuilder' is not defined`。

影响：默认 Agent 聊天主路径（含流式）在进入工具循环前即崩溃，等于本期 SSE 改动把对话打挂。

修复：补回 CitationBuilder 的 import（与 run_cancel 并存）；补一条 agent 单测防再丢。

### 2.2 重入库先删后写，失败/取消丢文档

位置：src/rag/ingest.py

- `_ingest_docx_file` / `_ingest_one_file`：内容有变化时先 `collection.delete(ids=existing_ids)`，再进 `_ingest_from_chunk_spool`
- `_ingest_from_chunk_spool`：仅在捕获 IngestCancelled 时 `_rollback_doc_chunks`；回滚只删「已写入的新块」，无法恢复已被删的旧块
- 非取消异常（embedding 失败、OOM、Chroma 写失败）连回滚都没有

影响：更新已有文档时，中途取消或任意失败 → 该 doc_id 在 Chroma 中消失；用户感知为「取消上传把原文档弄没了」。

修复：改为「写新成功再删旧」，或 staging doc_id / 快照恢复；失败与取消走同一恢复路径。

## 3. P1

### 3.1 load_skill 同轮只给 stub

位置：src/agent/core/tool_call_engine.py（约 218–242 行）；配套 src/agent/core/skill_loader.py 的 skill_ref_stub / hydrate_skill_refs

提交 ffe2027：成功 load_skill 后把 DB 内容换成 skill_ref，但 `llm_content = db_content`，当前轮 messages 也只剩 stub。hydrate_skill_refs 只在下一轮 run() 开头处理历史，不会修本轮内存里的 stub。

影响：模型刚加载 skill 后同轮继续推理时看不到正文，skill 驱动的工具链失效或胡答。

修复：DB 继续存 skill_ref；注入 messages 时用完整 `result.to_llm_str()`。单测覆盖「load_skill 后同轮第二次 LLM 调用能看到正文」。

### 3.2 入库面板仍用 crypto.randomUUID

位置：frontend/src/components/kb/IngestPanel.tsx（约 157 行）

d75ec7b 已为聊天路径引入 generateId（兼容裸 IP + HTTP 非安全上下文）。6974472 给入库加 ingest_id 时又写回 `crypto.randomUUID()`，未走 generateId。

影响：与线上部署场景一致时（http + 裸 IP），入库循环在发请求前抛错，取消 id 也无法建立。

修复：改为 `@/lib/id` 的 generateId。

### 3.3 取消入库存在竞态

位置：src/api/routes/kb.py `_ingest_event_stream`（约 291–321 行）；前端 IngestPanel cancel 会 abort SSE 并调 /kb/upload/cancel

问题链：

1. 客户端 abort 可能导致生成器在 wait_for(q.get()) 上收到 CancelledError，外层未捕获，未走 `_mark_cancelled()`
2. finally 里先 `unregister(ingest_id)`，再决定是否等任务；若 cancel_event 未置位，会 `await task` 把入库跑完
3. 前端 cancel API 若落在 unregister 之后，得到 cancelled=false，后台仍继续嵌入

叠加 2.2：即便取消信号生效，旧文档也可能已删、无法恢复。

修复：CancelledError / 断连一律 `_mark_cancelled()`；unregister 延后到任务结束；cancel API 与 SSE 生命周期对齐。取消时推送明确的 cancelled 终态事件（见 4.5）。

### 3.4 取消后 BM25 磁盘与 Chroma 不一致

位置：src/rag/ingest.py ingest_one（bm25_save=False，成功才 commit）；取消路径只改内存 BM25

Web 入库成功结束才 `commit_index`。取消时内存里 delete_by_doc_id / 回滚了，磁盘 pkl 仍是旧索引。进程重启或索引重载后，BM25 可召回已从 Chroma 删除的 chunk，回表正文为空，污染混合检索。

修复：取消/失败时重载磁盘快照，或对回滚结果 commit；或入库全程用隔离副本，成功再替换。

### 3.5 流式路径重复写语义缓存

位置：src/api/routes/chat.py（约 479–480 行）

f07415d 在原有 `_maybe_store_cache(...)` 下又加了一行完全相同的调用。

影响：每次成功流式回答写入两条语义缓存，Chroma 膨胀、trim 更激进、命中分布异常。

修复：删掉重复那一行。

### 3.6 空文档/零分块不清理旧数据

位置：src/rag/ingest.py `_ingest_one_file` / `_ingest_docx_file`

解析为空或 total_chunks == 0 时直接 `status="empty"` 返回，不删已有 Chroma / BM25 / kb_doc_index。

影响：文件被清空或无法再分块后，检索仍命中旧内容，L2 列表仍显示旧统计。

修复：empty 且已有 existing_ids 时，同步清理向量、BM25、文档索引与物理文件策略对齐产品预期。

## 4. P2

### 4.1 ingest_all 未失效缓存

位置：delete_all_kb_documents 只 unlink bm25_*.pkl；bm25_index 还有 .manifest.json / .chunks.jsonl

影响：管理巡检或磁盘上残留与空库不一致的 sidecar。

### 4.4 SSE 队列挤兑可能丢关键帧

位置：src/api/sse_outbound.py

- `_drop_one_mergeable` 回灌时 QueueFull 直接 break，drained 剩余项既不回队也不记日志
- critical 帧腾位后仍满则 warning 并丢弃（含 final_answer）
- chat 异常路径 `queue.put(error)` / sentinel 绕过 `_enqueue`，未先 flush token/thinking 缓冲；finally 里 `outbound.close()` 会丢掉缓冲中的尾部字

影响：高压或出错收尾时，前端可能缺终态或少一段已生成文本；DB 可能已有完整答案。

### 4.5 入库取消无终态 SSE 事件

位置：src/api/routes/kb.py 捕获 IngestCancelled 后只打日志，不推 cancelled/error

影响：依赖「流结束且无 result」的调用方易把取消当成失败；当前 IngestPanel 靠 cancelRef 兜底，契约仍脆。

### 4.6 trace 重写时 span 累积

位置：src/stores/trace_store.py record_trace：agent_traces 用 INSERT OR REPLACE，trace_spans 只 INSERT、不删旧

影响：同 trace_id 重试后瀑布图 span 重复、耗时统计偏大。（若本期改动触达了该写入路径则一并修。）
