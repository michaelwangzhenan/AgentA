# 背景

在 [post](./i1.1_16_post_deploy.md) 中实现了页面底部产品链接入口，但没有真实页面。
本期实现所有未实现的页面，考虑：
1. 权限：谁可以看到
2. 内容：展示是什么
3. 样式：如何展示的更美观


# 需求分析

## 1. 目标

把底栏 4 个仍为「页面建设中」的产品链接做成真实页面，与已上线的「联系我们」（/contact）一致：未登录可访问、登录后也可从底栏进入，视觉与对外站点气质统一。

本期范围仅这 4 页，不改动联系我们页逻辑，不顺带改底栏备案区样式。

## 2. 现状

| 底栏项 | 路由 | 状态 |
|---|---|---|
| 关于 AgentA | 无 | 点击 toast「页面建设中」 |
| 使用须知 | 无 | 同上 |
| 帮助中心 | 无 | 同上 |
| 隐私政策 | 无 | 同上 |
| 联系我们 | /contact | 已实现，公开路由 |

实现参考：

- 路由：App.tsx 里 /contact 在登录前后均注册，未登录深链会暂存目标，登录后回跳（/contact 除外）
- 页面：ContactPage 单卡片居中，读 frontend/public/site.json
- 对外文案：PublicHero（登录页左侧）已有产品一句话 + 三条特性，可作「关于」页素材

## 3. 页面清单

### 3.1 关于 AgentA（/about）

面向访客的产品介绍，回答「这是什么、能做什么、适合谁」。

建议内容结构：

1. 标题 + 一句话定位（与 PublicHero 对齐：个人 AI 学习助手）
2. 核心能力 3～5 条（RAG 与溯源、学习闭环、Skills/MCP、多模型、本地私有部署等，摘自 README / PublicHero，措辞面向访客而非开发者）
3. 技术亮点可选一段（开源、可自托管），链到 GitHub（site.json contact.github）
4. 底部操作：未登录 →「立即体验」跳登录页并聚焦访客按钮；已登录 →「进入应用」跳 /chat

权限：公开，与 /contact 相同。

### 3.2 使用须知（/terms）

面向所有使用者的规则说明，偏「用之前要知道的事」，不是功能教程。

建议章节：

1. 账号与访问：不开放注册；体验账号与升档方式（链到 /contact）
2. 角色与权限：readonly / user / admin 三档读广写窄（与 i1.1_17 一致）；主账号管用户
3. 内容与合规：用户上传资料须合法自有；禁止违法、侵权、滥用
4. 服务性质：演示 / 自用部署，不承诺 SLA；模型输出仅供参考
5. 变更：条款可更新，以页内日期为准

权限：公开。登录用户从设置或底栏进入看到同一正文。

### 3.3 帮助中心（/help）

面向访客的精简自助说明（本期不做分章操作手册）。

固定结构：

1. 快速开始：访客一键体验 → 浏览界面；要写入或升档 → /contact
2. 常见问题 5～8 条：体验账号、角色区别（readonly 只读 / user 可写核心 / admin 含高级）、不开放注册、如何申请权限、数据存在哪、模型报错怎么办等
3. 页末：链到 GitHub README / 仓库（site.json contact.github）

权限：公开。

### 3.4 隐私政策（/privacy）

合规向文档，说明收集哪些数据、用途、存储位置、保留与联系方式。

建议章节（标准结构，实施前需你确认或提供正文）：

1. 适用范围
2. 我们收集的信息（账号、会话、上传文档、用量日志、技术日志等——与 AgentA 实际存储对齐）
3. 使用目的与法律依据
4. 存储与本地化（自托管实例数据在部署者磁盘，非 SaaS 多租户）
5. Cookie / 会话
6. 第三方（LLM API、可选 MCP）
7. 用户权利与行使方式（联系部署者）
8. 政策更新与生效日期

权限：公开。备案审核可读。

## 4. 权限与路由

原则：4 个新路由均与 /contact 同级——不要求登录，登录状态不影响正文。

| 路由 | 页面 | 未登录 | 已登录 |
|---|---|---|---|
| /about | 关于 | 可访问 | 可访问 |
| /terms | 使用须知 | 可访问 | 可访问 |
| /help | 帮助中心 | 可访问 | 可访问 |
| /privacy | 隐私政策 | 可访问 | 可访问 |

App.tsx 改动：

- 注册 4 条公开 Route（登录前、登录后各一份，与 contact 并列）
- 深链回跳白名单：与 /contact 一样，这 4 条路径登录后不应强制留在静态页（可选：登录后仍停留当前页也可接受，需定一种行为）

SiteFooter：4 项 href 从 null 改为对应路径，去掉 showComingSoon。

## 5. 样式与布局

目标：比单条 toast 可信，又不抢登录页主视觉；长文可读。

建议统一静态页外壳 StaticPageShell（或复用并扩展 PublicPageShell）：

- 全屏可滚动，max-w-2xl 或 max-w-3xl 居中
- 顶栏：页面标题 + 可选副标题
- 正文：prose 排版（标题层级、列表、链接样式），支持深色模式
- 底栏 SiteFooter 保留；内容区 pb 与现网一致防遮挡
- 页脚操作区：返回登录 / 进入应用（与 ContactPage 相同模式）

与 ContactPage 差异：联系我们偏表单式信息块；关于 / 须知 / 帮助 / 隐私偏长文，需要更好的段落间距与目录（帮助中心、隐私政策可考虑页内锚点目录）。

登录页 PublicHero 不在静态页复用（避免双栏过窄挤长文）；关于页可在正文顶部放小号 logo + 标语。

## 6. 内容维护（已确认）

采用 public/pages/*.md，浏览器运行时 fetch 渲染：

- about.md、terms.md、help.md、privacy.md 放 frontend/public/pages/
- 部署时与 site.json 相同：只改文案可 cp 到 frontend/dist/pages/，无需整包 rebuild
- 需引入轻量 Markdown 渲染（如 react-markdown），样式用 prose 类统一
- 隐私政策：由实施方先写一版贴合 AgentA 自托管场景的模板，你再按需改 md

## 7. 验收标准

1. 底栏 4 链接均可点击跳转，不再出现「页面建设中」
2. 未登录可直接打开 /about、/terms、/help、/privacy，正文完整可读
3. 已登录从主界面底栏进入上述页面，可返回 /chat
4. 移动端窄屏下长文可滚动，不被底栏遮挡
5. 深色模式下文字对比度正常
6. 隐私政策页含生效日期；使用须知与当前角色体系（readonly/user/admin）描述一致
7. 帮助中心至少覆盖：访客体验、升档路径、只读与可写区别

## 8. 设计测试

| 场景 | 操作 | 预期 |
|---|---|---|
| 访客 | 登录页底栏点「关于 AgentA」 | 进入 /about，可见「立即体验」 |
| 访客 | 直接访问 /privacy | 200，显示隐私正文 |
| user 登录 | 底栏点「帮助中心」 | 进入 /help，可见「进入应用」 |
| 窄屏 | /terms 滚动到底 | 最后一段不被 SiteFooter 遮住 |
| 配置 | 修改正文源文件后刷新 | 开发环境热更新或刷新可见（取决于内容方案） |

自动化（可选）：前端路由 smoke——未登录 fetch 四路径渲染标题；SiteFooter 链接 href 断言。
