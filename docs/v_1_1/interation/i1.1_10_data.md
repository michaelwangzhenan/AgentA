# 项目资料

## 脱敏要点和规则
项目资料是公司资料，上传到 VPS 需要进行信息脱敏。
具体规则：

### 内容处理

以下内容不得上传 VPS，也不得进入知识库、评估题或检索日志：

1. 公司名称、商标、内部使用声明、内部模板和版权受限素材。
2. 员工、客户、合作方及评审人员的姓名、联系方式和其他身份信息。
3. 内部功能编号、需求编号、问题单、研发条目、代码名称和版本计划。
4. 内网地址、内部文件路径、内部系统名称、账号及访问凭据。
5. 未公开的算法、公式、参数、阈值、默认值、处理流程和实现限制。
6. 产品架构、硬件配置、客户网络配置、设备标识和部署信息。
7. 内部测试环境、测试数据、性能结果、故障信息、评审意见和待确认事项。
8. 图片、图表、截图、备注、批注、超链接和附件中包含的上述信息。

可以保留公开标准已经定义的概念、术语和协议行为，但必须依据公开资料重新编写并注明来源。不得复制公司资料后仅替换公司名、人员姓名或功能编号，也不得保留从内部参数、测试数据和实现细节推导出的结论。

无法确认是否公开的信息按敏感信息处理，不上传、不入库。

### 文件处理

1. 原始公司文件不得上传 VPS，也不得通过 Web 入库接口临时存储。
2. 脱敏必须在本地完成，并新建不含原文件内部结构的派生文档。
3. 不复制原文件的图片、母版、备注、批注、超链接、附件和文档属性。
4. 需要保留的示意图应重新绘制；不得用遮挡框覆盖敏感文字。
5. 入库前同时检查正文、图片文字、备注、链接、元数据和嵌入对象。
6. 脱敏文档应能脱离原文件单独审查，不能依赖原文件理解内容。

### 入库检查

1. 只上传审查通过的派生文档，原始文件始终保留在本地受控目录。
2. 文档生成的评估题、答案和标签执行相同的脱敏规则。
3. 检查检索片段、引用原文、下载接口和运行日志，确保不会返回敏感信息。
4. 每份派生文档记录公开资料来源，保证内容可以追溯和复核。
5. 入库前搜索公司名、内部域名、人员姓名、编号和参数名；发现命中后人工复核。
