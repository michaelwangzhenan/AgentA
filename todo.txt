3. 重排序（Reranking）=> Done
  目标： 在向量检索结果上加 Cross-Encoder 二次排序，提升精度
  详细实施计划：
    【背景】
      当前 retriever.py 采用两个 Bi-Encoder（SentenceTransformer）+ round-robin 合并：
        · all-MiniLM-L6-v2     → 英文向量化入库 / 召回 kb_en collection
        · BAAI/bge-small-zh    → 中文向量化入库 / 召回 kb_zh collection
      Bi-Encoder 速度快但精度有限——它将 query 和 document 各自单独编码，
      无法捕捉两者之间的细粒度语义交互。

      Reranking 引入第三个模型 Cross-Encoder（ms-marco-MiniLM-L-6-v2）作为二阶段精排：
        · 三个模型职责不同，互不替代，同时工作：
            阶段一（召回）：两个 Bi-Encoder 各自查询 → round-robin 合并取 top_k×3 候选
            阶段二（精排）：Cross-Encoder 对候选逐对打分 → 降序重排 → 截取最终 top_k 条
        · RERANKER_ENABLED=false 时跳过阶段二，两个 Bi-Encoder 行为完全不变（向后兼容）

      三个模型对比：
        模型                       职责          输入          特点
        all-MiniLM-L6-v2          英文召回       单个文本      速度快，支持批量入库
        BAAI/bge-small-zh         中文召回       单个文本      速度快，支持批量入库
        ms-marco-MiniLM-L-6-v2    精排打分       (query, doc)  精度高，不可用于入库

    【选型】
      模型：cross-encoder/ms-marco-MiniLM-L-6-v2（约 23MB，推理极快，中英双语）
      包：sentence-transformers（已安装，CrossEncoder 类在其中，无需新增依赖）
      缓存：首次下载后通过 TRANSFORMERS_OFFLINE=1 完全离线运行

    【实施步骤】

    1. src/rag/reranker.py — 新建 Reranker 模块
       - 封装 CrossEncoder，对外暴露 rerank(query, hits, top_k) -> list[_Hit] 接口
       - 懒加载（首次调用时才初始化模型），避免影响无需 rerank 场景的启动速度
       - 模型名通过 config.RERANKER_MODEL 读取
       - 候选数 ≤ top_k 时直接透传，不做无意义的重排

    2. src/config.py — 新增配置项
       - RERANKER_MODEL: str = os.getenv("RERANKER_MODEL", "cross-encoder/ms-marco-MiniLM-L-6-v2")
       - RERANKER_ENABLED: bool = os.getenv("RERANKER_ENABLED", "true").lower() == "true"
       - RERANKER_RECALL_MULTIPLIER: int = int(os.getenv("RERANKER_RECALL_MULTIPLIER", "3"))

    3. src/rag/retriever.py — 集成 Reranker
       - search() 召回窗口扩大为 top_k × RERANKER_RECALL_MULTIPLIER
       - RERANKER_ENABLED=true 时调用 reranker.rerank()，否则直接使用 round-robin 结果

    4. .env.example + .env — 补充三个新配置项注释，.env 默认开启 RERANKER_ENABLED=true

    5. tests/test_phase3_rag.py — 新增测试
       - 单元测试：rerank() 返回数量 ≤ top_k、分数降序排列
       - 单元测试：候选数 ≤ top_k 时直接透传，不调用 CrossEncoder
       - 单元测试：RERANKER_ENABLED=false 时 search() 跳过 rerank（mock 验证未调用）
       - 集成测试（integration marker）：真实 query 重排后 top-1 相关性高于重排前

    6. README — 更新项目结构（新增 reranker.py）、配置项说明、工作流程图

    【模型下载（首次）】
      $env:TRANSFORMERS_OFFLINE="0"; $env:HF_ENDPOINT="https://hf-mirror.com"
      .venv\Scripts\python -c "from sentence_transformers import CrossEncoder; CrossEncoder('cross-encoder/ms-marco-MiniLM-L-6-v2'); print('OK')"
      下载完成后恢复 TRANSFORMERS_OFFLINE=1

    【风险与边界】
      - 模型冷启动：首次调用 CrossEncoder 约需 1-2 秒加载，后续调用毫秒级
      - 召回窗口倍数：默认 3（即 top_k=5 时取 15 条候选再精排），可通过环境变量调整
      - 两个 collection 都为空时，round-robin 阶段已返回空，rerank 不会被调用

8. 优化 ReAct => Done
  目标： 提升 Agent 在多轮对话中的推理能力和工具调用效率，具体包括：
    · 动态工具选择策略：根据问题类型优化 System Prompt，引导 LLM 更准确地决策何时调用哪个工具
    · 工具调用失败重试：工具执行出错时自动重试或降级，而非直接返回失败
    · 多步骤任务规划：支持 LLM 在单次 run() 中拆解复杂任务并按步骤执行
    · 工具结果质量判断：LLM 能识别工具返回内容为空/无关时主动切换策略，而非直接生成回答
  详细实施计划：

    【现状分析】
      agent.py run() 循环已支持多轮 tool_calls，但存在以下问题：
        1. 工具执行异常由 execute_tool() 内部 try/except 消化后返回错误字符串，
           LLM 看到 "错误：..." 后倾向于直接生成失败回答，不会自动重试
        2. SYSTEM_PROMPT 未告知 LLM"看到工具返回错误时应重试或换策略"
        3. MAX_ITERATIONS=10 无分层保护：全部轮次耗尽后才发现是因为反复失败重试
        4. 工具结果没有结构化标注（成功/失败/空结果），LLM 靠内容推断，可靠性低
        5. execute_tool() 抛出 ValueError（未知工具）时，run() 未捕获，会崩溃

    【实施步骤】

    1. src/agent/tools.py — 工具结果结构化封装
       新增 ToolResult dataclass：
         @dataclass(frozen=True)
         class ToolResult:
             status: Literal["ok", "empty", "error"]
             content: str
             def to_llm_str(self) -> str  # 返回给 LLM 的格式化字符串，使用 [工具成功]/[结果为空]/[工具失败] 前缀标签
       修改 _tool_search_knowledge()：
         - 检测返回内容是否包含来源标记 "[1]"（有 → ok；无 → empty），与文案解耦
         - 正常内容 → status="ok"
       修改 _tool_fetch_url()：
         - 以 "错误：" 开头 → status="error"；内容为空 → status="empty"；否则 "ok"
       修改 execute_tool()：
         - 返回 ToolResult 而非裸字符串
         - 用 try/except Exception 兜底捕获所有异常（含未知工具 ValueError），返回 status="error"，
           不再向上抛出异常，消除 run() 的崩溃风险

    2. src/agent/agent.py — tool message 引导文字 + SYSTEM_PROMPT 第 5 条
       【删除】_run_tool_with_retry()：Python 层静默重试绕过 LLM 推理，违反 ReAct 范式；
               应由 LLM 在下一轮推理中主动决定是否换策略/换工具/换 URL
       新增常量：
         TOOL_EMPTY_HINT: str  # 知识库空结果时追加给 LLM 的引导提示（放在 tool message 末尾）
       修改 run() 中工具执行部分：
         - execute_tool() 返回 ToolResult，写入 messages 时用 result.to_llm_str()
         - status="error" 时，在 tool message content 末尾追加
           "\n\n[提示] 请换一种方式（换参数或换工具）重试，不要直接回答"
         - status="empty" 且工具是 search_knowledge 时，追加 TOOL_EMPTY_HINT 提示，
           引导 LLM 下一轮改调 fetch_url
       在 SYSTEM_PROMPT "## 工具使用策略"末尾新增第 5 条：
         5. 若工具返回 [结果为空] 或 [工具失败]：
            - search_knowledge 返回 [结果为空] → 立即改调 fetch_url 补充搜索，不允许直接回答
            - fetch_url 返回 [工具失败] → 换一个同类型的备选 URL 重试（最多换 2 次）
            - 两种工具均无法获取有效信息时，才如实告知用户"当前无法获取相关信息"

    3. src/agent/agent.py — 迭代次数分层保护
       将单一 MAX_ITERATIONS 拆分为两个维度：
         MAX_TOOL_ROUNDS: int = 8    # 最多 8 轮含 tool_calls 的推理（防止工具死循环）
         MAX_TOTAL_ROUNDS: int = 12  # 含最终回答在内的总推理轮次上限
       run() 中增加 tool_rounds 计数器：
         - 每次 message.tool_calls 触发时 tool_rounds += 1
         - tool_rounds >= MAX_TOOL_ROUNDS 时，下一轮 chat() 调用改为 tools=None（不传工具定义），
           LLM 无工具可调，自然生成文本回答——消息序列格式合法，不违反 OpenAI 协议
       保留原 max_iterations 参数签名不变（默认值改为 MAX_TOTAL_ROUNDS），向后兼容

    4. tests/ — 同步更新测试
       tests/test_phase4_tools.py：
         - execute_tool() 返回类型从 str → ToolResult，所有字符串断言改为 .content 属性访问
         - 新增：未知工具名返回 status="error" 而非抛 ValueError
       tests/test_phase5_agent.py — 新增 TestToolGuidance 类：
         - test_error_result_appends_hint：工具返回 error 时 tool message content 含"[提示]"
         - test_empty_knowledge_appends_empty_hint：search_knowledge 返回 empty 时含 TOOL_EMPTY_HINT
         - test_tool_rounds_limit_disables_tools：tool_rounds 达上限时 chat() 以 tools=None 调用
         - test_total_rounds_limit_fallback：超过 MAX_TOTAL_ROUNDS 时返回兜底回答
       修改已有 TestAgentInit：
         - 验证 max_iterations 默认值为 MAX_TOTAL_ROUNDS

    【涉及文件】
      src/agent/tools.py         — ToolResult dataclass、execute_tool() 返回类型变更
      src/agent/agent.py         — 引导文字、tools=None 降级、分层计数、SYSTEM_PROMPT 第5条
      tests/test_phase4_tools.py — 断言适配 ToolResult.content + 新增未知工具测试
      tests/test_phase5_agent.py — 新增 TestToolGuidance（4 个测试）+ 修改 TestAgentInit

    【注意事项】
